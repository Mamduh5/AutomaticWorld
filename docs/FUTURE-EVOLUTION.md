# Future Evolution

Recommended next work:

1. Establish a reviewed procedure for updating runtime digests and recording multi-platform provenance.
2. Evaluate a narrowly scoped Windows-native reparse metadata check if Node's `lstat`/`realpath` coverage proves insufficient.
3. Add supervised execution tiers and stronger runtime policy enforcement without exposing image selection or network.
4. Improve memory consolidation and retrieval evaluation while retaining strict agent ownership and local operation.
5. Add a read-only activity API/dashboard and operational health metrics.
6. Exercise longer bounded autonomous runs only after Docker and cognition-provider prerequisites are operationally verified.
7. Only after sustained evidence of safe persistence, reusable technology, two-way Owner communication, and stable operation, review a descendant proposal with explicit resource costs, partial cultural inheritance, and no complete memory copy.

Inhabitants may eventually request independent external identities through an explicit world capability and a separate policy/provisioning boundary. Such a design must define provider policy, ownership, resource cost, revocation, credential isolation, and audit behavior. It must not expose browser automation, arbitrary account registration, mailbox passwords, or the shared world transport identity. No inhabitant-specific external identity is implemented now: Mam and Toey continue to use `SEND_MESSAGE -> owner:external`, and the trusted gateway alone selects the shared world mailbox.

Birth/reproduction is not an action. There are no genomes, mutations, mates, or population expansion in this milestone. None of these future steps prescribe what Mam or Toey should value, attempt, or become.

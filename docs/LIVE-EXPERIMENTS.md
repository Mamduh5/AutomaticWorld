# Live Experiments

Live trials observe existing Mam and Toey without assigning work, changing the foundational instruction, resetting history, replenishing resources, or sending an Owner message. Provider choices are `openrouter`, `openai`, and `opencode-zen`. For Zen, set `COGNITION_PROVIDER=opencode-zen`, `OPENCODE_ZEN_API_KEY`, and `OPENCODE_ZEN_MODEL=space-bunny-free` in ignored `.env`; the default base URL is `https://opencode.ai/zen/v1`. These are Owner infrastructure values; agents do not observe the provider, model, endpoint, token accounting, or credentials.

## Resource migration prerequisite

Before any resume/run/experiment, inspect `world resources migration-status`. A legacy universe requires the explicit paused preview/apply workflow in [resource laws](RESOURCES-ECONOMY.md). Migration creates zero Cognition Credits; any later credit supply requires a separate authoritative Owner allocation. `doctor --integrity-only` reads SQLite and ledger integrity without external calls. The protected T1805 world must remain paused and unmigrated until the Owner chooses otherwise.

## Safe sequence

1. While paused, run `pnpm world checkpoint create <label>`.
2. Run the deterministic gate with `pnpm check`.
3. Resume the world, then run `pnpm world doctor --live`.
4. Start an explicitly bounded trial with `pnpm world experiment --live --label <label> --ticks <n>`. This uses the conservative default profile. Select `--profile long` only for a deliberate long observation, or supply explicit cognition-turn, input-token, output-token, Cognition Credit, Local Compute, execution, and wall-clock overrides. On Windows, the standard long command is `npm.cmd run world -- experiment --live --ticks 500 --profile long`.
5. Inspect `pnpm world run-report <label>` and `pnpm world experiment-report <label>`.
6. Pause if no further run is intended and verify doctor/integrity state after restart.

The live doctor verifies the database, exact founder identities, population, running state, lease, Docker isolation, runtime image identity, resource model/ledgers/holds, cognition availability, storage, reconciliation, tool-store integrity, secret isolation, provider selection/configuration/authentication connectivity, and configured Owner transports. For Zen it uses authenticated `GET https://opencode.ai/zen/v1/models` and checks whether the configured model ID appears. This consumes no inference tokens and does not establish that generation or account credit works. LINE is optional for cognition readiness; a partial LINE deployment is reported as a warning.

Every run stores factual preflight and postflight snapshots. Action attribution records run ID, tick, agent, action type, result, safe action metadata, provider usage, and latency. It does not store hidden reasoning. The stagnation report counts wait-only sequences, repeated action types, repeated/consolidated memories, and turns without artifact changes; it never changes behavior.

## Local cognition fault recovery

The complete input, including delivery/cursor identifiers and truncation metadata, stays within `COGNITION_INPUT_BUDGET_TOKENS=8000`. A deterministic context/request preparation or recovery fault is a local kernel failure. It records Owner-only `COGNITION_LOCAL_ERROR`, stops with `local cognition preparation failure: <phase>/<code>`, and pauses the world and any unfinished scheduler at the same committed tick. There is no synthetic WAIT, observation consumption, cursor advancement, credit consumption, provider cooldown or breaker increment for that fault. No automatic same-fault retry runs while paused.

Before a cognition opportunity exists there is no credit hold. After its durable creation, the same hold and frozen context survive the stop; a successful already-consumed output is reused under the existing recovery model. Do not manually clear holds, opportunities or scheduler progress. Earlier completed inhabitants are not repeated. Inspect `status`, `doctor --integrity-only`, `activity --last 100`, `run-report <label>` and `debug provider-cooldown` while paused, correct the diagnosed local defect, then explicitly resume and run a bounded experiment. A locally paused schedule without a provider suspension emits no provider retry event on restart.

Reports expose `localCognitionFailures`, `providerFailures` and `providerSuspensions` separately. Historical generic `COGNITION_PROVIDER_ERROR` entries keep their recorded provenance; there is no retroactive relabeling. Timeout, transport, 408, 429, 5xx, short retry, durable suspension and provider parse/schema fallback semantics remain unchanged.

Experiment token ceilings are aggregate AutomaticWorld accounting limits, distinct from the fixed per-cognition context budget and from provider rate limits, availability, or account quotas. Limits are evaluated after a complete world-tick scheduling boundary. Consequently, a completed boundary may produce bounded overshoot equal to the provider usage of the cognition calls completed in that boundary; usage is never reset, hidden, or discarded.

For `--profile long`, terminal retryable infrastructure unavailability pauses simulation progress: timeout, transport failure, HTTP 408, HTTP 429, or HTTP 5xx. Response parse/schema failures and HTTP 400/401/403/404 keep the bounded short retry and fallback behavior. A suspension backs off in operational real time, retries the same frozen cognition context, and resumes after a valid provider response. The provider/model scope is cooled globally for that tick, so another inhabitant using that same scope is not called before the pending opportunity is resolved. The exponential defaults are 2s, 4s, 8s, 16s, 32s, then 60s; valid `Retry-After` values are honored up to the 30-minute maximum suspension. The one pending Cognition Credit remains reserved across retries. No fallback WAIT, autonomous action, credit consumption or Local Compute charge, cursor advancement, memory, sleep change, or `TICK_COMPLETED` is produced solely by cooldown. A provider timeout is not an inhabitant WAIT. The ordinary profile keeps its conservative failure/fallback behavior.

The unfinished scheduler boundary is stored in the authoritative database. If another inhabitant already completed its part of the tick, that completion is retained and is not run twice after restart. Ctrl+C during cooldown cancels future retries promptly, marks the cooldown aborted, preserves the pending journal, and releases the lease. Resume with the same long command and provider/model configuration. Suspension time counts toward `maxWallClockMs`; reaching that ceiling or the maximum suspension stops cleanly without advancing world time. The lease heartbeat continues on timer turns throughout the wait.

Use `pnpm world debug provider-cooldown` to inspect the read-only cooldown, safe cause, and durable tick progress, and `pnpm world debug runner-lease` to inspect lease health. Operational `PROVIDER_COOLDOWN_STARTED`, `PROVIDER_COOLDOWN_FAILURE`, `PROVIDER_COOLDOWN_RETRY`, `PROVIDER_COOLDOWN_RECOVERED`, and `PROVIDER_COOLDOWN_ABORTED` events and run-report metrics are Owner-only kernel facts; they are not delivered as inhabitant knowledge. The rate-limit report fields remain 429-only; generic provider-suspension fields include timeout, transport, and eligible HTTP failures. `providerHttpAttemptsRecorded` and `shortProviderRetriesRecorded` cover attempts recorded in event metadata, including handled suspension failures. `providerAttemptsWithUnknownUsage` records requests without authoritative provider usage; zero recorded tokens on a failed turn must not be read as zero upstream consumption. The ordinary infrastructure circuit breaker remains active for non-handled failures, while handled long-profile suspensions do not count as failed world turns.

An unfinished scheduler is fenced to its original provider and model. Changing `.env` does not migrate it. While the world is paused and no runner lease exists, use `pnpm world pending-provider show`, then explicitly use `pnpm world pending-provider migrate --provider opencode-zen --model space-bunny-free`. This performs a read-only target readiness check before an atomic routing change, keeps the frozen context and agent state, and clears the old cooldown. Compare the context SHA-256, resources, cursors, tick, agent order, and completed IDs in `pending-provider show` before and after; then resume before a live experiment. An absent model, 401, 403, 404, 429, or 5xx from the models endpoint prevents migration without changing the pending scheduler. The migration event stays Owner-only.

`space-bunny-free` is limited-time and externally controlled. Its currently free price is not an unlimited-throughput promise. Zen has paid models and separate account auto-reload/billing preferences. Confirm the exact model and those account settings before live use. AutomaticWorld never switches to a paid model automatically. Provider prompt and completion token counts continue to count normally when usage is returned.

Checkpoints are disaster recovery references, not alternate worlds or automatic rollback. Only the Owner CLI can create one, and restoration remains an explicit future operation. Inhabitant mistakes are not a restoration reason.

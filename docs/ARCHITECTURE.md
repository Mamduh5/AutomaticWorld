# Architecture

The kernel separates persistent state, cognition, observations, validated actions, filesystem effects, container execution, memory retrieval, resource accounting, messaging, and external Owner delivery.

SQLite stores practical state in `world`, `agents`, `messages`, `memories`, `executions`, `owner_outbox`, `owner_deliveries`, `owner_ingress`, `artifact_revisions`, `filesystem_operations`, `tools`, `tool_versions`, `tool_invocations`, `autonomy_runs`, `observation_cursors`, and `runner_lease`. The append-only `events` table remains the historical audit stream rather than the only state store. Base schema initialization supports new worlds; persisted legacy worlds are not automatically upgraded on read-only open. The resource model requires explicit Owner migration, and Genesis refuses on an existing unmigrated universe.

An observation contains only compact self/world state, newly delivered addressed messages, newly visible bounded causal event projections, a small recent peer-conversation window, a small event-continuity window, separately listed bounded private/shared artifact names, bounded recent self-owned executions, relevant self-owned memories, resources, structured kernel capability descriptions, and a bounded accessible userland-tool view. `LIST_INHABITANTS` exposes active identity/lifecycle plus cognition dormancy, resource totals/holds and capital by currency. It excludes private files, memories, messages and provider/payment configuration. Cognition has no repository, filesystem, environment, gateway, or Docker access. `LIST_TOOLS` remains the exhaustive intentional tool-discovery action.

Each inhabitant has a durable `observation_cursors` row with independent message, own-event, and shared-event positions. Existing worlds initialize these positions from the last persisted successful-cognition input boundary, leaving later action results pending; fresh inhabitants start at their creation boundary. A successful cognition response advances only the portions actually submitted. Provider failure leaves every position unchanged. Runner-driven advancement checks both the optimistic prior cursor values and the live lease token in one SQLite transaction, so restart preserves unseen inputs and stale runners cannot consume them. Events, messages, artifacts, and memories remain immutable source records.

The deterministic context builder prioritizes new messages, own causal consequences including `ACTION_RESULT`, newly shared consequences, recent peer conversation, recent self activity, a private working set of the two most recently and successfully read distinct text artifacts, ranked local memories, compact state, bounded tool/execution views, and a short already-observed event-continuity window. Recent peer conversation selects up to four distinct persisted agent-to-agent messages involving the inhabitant, then displays them chronologically with tick, sender, recipient, and bounded factual content. Incoming messages qualify only through the already-advanced observation cursor; the current turn's new messages cannot appear there. Own outbound messages need no inbound cursor. Other inhabitants' conversations and Owner messages are excluded. The section has an 800 estimated-token cap and yields to mandatory new observations under the unchanged total budget. Recent self activity selects up to six distinct own `ACTION_RESULT` records at or before the inhabitant's committed own-event cursor and displays them chronologically. Each entry shows tick, action type, success or failure, safe target facts, and compact result facts. It omits file contents, execution output, and tool output; intentional `WAIT` is an action, while provider fallback is not. A result delivered as a new consequence in the current context cannot appear in this history. The self-activity section has its own 800 estimated-token cap and yields to mandatory new observations and peer conversation within the unchanged total budget. Both sections are factual context projections, not memory, task tracking, or workflow state; the kernel performs no contradiction resolution. Working artifacts are reconstructed from the same inhabitant's durable authorized `READ_FILE` results, refresh by `(space, path)`, use stable bounded content projections, and are dropped oldest-first when mandatory context leaves insufficient budget. Large strings and arrays use stable first/last projections with byte counts, hashes, and truncation markers. `COGNITION_INPUT_BUDGET_TOKENS` defaults to 8000, uses a conservative three-UTF-8-bytes-per-token estimate, and reserves a separate 2000-token output allowance. The budget value and cursor internals are Owner diagnostics and are not included as inhabitant instructions. `world debug cognition-context <name-or-id>` previews section sizes, working-artifact metadata, selected identifiers, pending observations, and truncation without advancing any cursor or calling cognition.

Every bounded projection is estimated as part of the complete provider input, including all embedded identifiers, byte/hash/count/truncation fields and delivery arrays. New message IDs, own observation/result IDs, shared consequence IDs and continuity IDs join their content before admission; rejection removes the entire bundle before cursor proposals are calculated. Optional sections retain their existing priority and caps. The final context and any recovered frozen context must fit the configured budget.

`LocalCognitionPreparationError` identifies local context/request/opportunity preparation, persisted-context recovery and cognition commit faults. The engine records safe `phase`, `code`, committed tick and hold status in Owner-only `COGNITION_LOCAL_ERROR`, pauses the world and unfinished scheduler, and rethrows. The runner terminates with `local cognition preparation failure: <phase>/<code>` without a provider fallback, cooldown or breaker increment. Pre-reservation failure creates no hold; an existing hold/opportunity is preserved, including a consumed successful output for exactly-once recovery. Earlier completed peer boundaries survive. Explicit correction/resume is required, preventing an automatic fault loop. Provider invocation/response-validation failures retain their existing provider behavior.

The world validates a proposed action before tool dispatch. File tools cause real staged artifacts. `EXECUTE_PROGRAM` runs an existing private artifact through `ExecutionSandbox`; the Docker implementation mounts only that workspace. Actual exit status/stdout/stderr are persisted, exposed in later observations, and summarized as episodic evidence—not as an XP or skill claim.

`PROGRAM_EXECUTION_STARTED` with `boundary: sandbox_dispatch` is emitted after successful maximum Local Compute admission immediately before calling the sandbox. It proves dispatch, not container/process launch: Docker image verification is inside `execute()`. `TOOL_INVOKED` uses the equivalent boundary. Cached execution recovery emits neither dispatch event again. Insufficient execution admission produces ordinary `ACTION_FAILED`/`ACTION_RESULT` diagnostics with required reservation and available capacity, without execution rows, outcomes or resource debit.

`PUBLISH_TOOL` snapshots a bounded multi-file private source tree into `world-data/system/tool-store/<sourceHash>`. SQLite records the opaque inhabitant-selected name, publisher, runtime, manifest, version link, and store path. `INVOKE_TOOL` resolves and re-hashes that protected snapshot, checks private/shared access, sends bounded JSON on stdin, and persists the real execution and invocation. Output can influence later cognition, but untrusted code cannot mutate world state directly.

Filesystem mutation coordination journals the expected before/after hash and byte boundary before promotion. Startup reconciliation compares the durable target with those hashes: an unpromoted mutation is marked failed, a promoted mutation completes its one SQLite accounting/revision/event transaction, and an unexpected target is marked failed and audited. Database commits are idempotent, and orphan staging/backup files are recursively cleaned within authorized roots.

World events are immutable Owner audit history, not automatically inhabitant observations. A deny-by-default visibility policy classifies the bounded causal event set as `AGENT_VISIBLE`; provider, runner, checkpoint, reconciliation, lease, circuit-breaker, and unknown event types are `OWNER_KERNEL_ONLY`. Completed cognition actions, including ordinary action failures, persist a scoped `ACTION_RESULT` so later cognition can observe what happened; infrastructure failures do not enter that action history. Memory records retain source-event/source-run provenance plus an Owner-visible retrieval status, and kernel-only source events cannot create retrievable inhabitant memory.

Agent-to-Owner messages first enter `owner_outbox`. `OwnerGatewayDispatcher` records success per transport, skips successful transports on retry, and marks the aggregate outbox delivered only when every enabled transport succeeds. Console, SMTP email, and LINE push are kernel-selected adapters. Email authentication and `From` use one kernel-owned world mailbox; the independently configured Owner destination is only the recipient.

Owner-to-agent CLI and LINE messages enter the transport-independent `OwnerIngressService`. Acceptance and external event identity are durable before asynchronous LINE routing. Only explicit recipient syntax is accepted; delivery becomes an ordinary persistent `owner:external` message and uses the existing direct-message wake rule.

Continuous operation uses a renewable SQLite lease. Status and process existence are distinct: `running` permits cycles, while an explicit CLI process performs them. A database status never auto-launches a runner.

Bounded continuous/live experiments create `autonomy_runs` records with a factual label, model identifier, preflight/postflight snapshots, event boundaries, successful-turn/token/Cognition Credit/Local Compute/execution/tick/wall limits, and termination reason. `COGNITION_TURN_COMPLETED`, `MEMORY_RETRIEVED`, and `AUTONOMY_ACTION` provide run/tick/agent/action/result attribution without storing hidden reasoning. The runner opens a circuit breaker for repeated provider or Docker-infrastructure failures, but not for an inhabitant program's ordinary nonzero exit. Reports derive factual counts from persisted events. Run and experiment reports separately count `localCognitionFailures`, `providerFailures` and `providerSuspensions`; legacy generic provider errors keep their original classification.

Owner-only checkpoints use SQLite's online backup API and regular-file copies of agent, shared, and system/tool-store artifacts. Database and artifact hashes plus the absolute backup reference are recorded; restoration is never automatic and checkpoint creation is not an inhabitant capability.

## Resource economy persistence

The [v2 resource design](RESOURCES-ECONOMY.md) adds `resource_model`, `value_accounts`, immutable `value_ledger`, `value_reservations`, immutable `reservation_journal`, `resource_purchase_requests`, `cognition_opportunities`, `action_outcomes`, `execution_outcomes` and `resource_run_snapshots`. `EconomyService` owns atomic accounting and idempotency. The journal distinguishes resource units from currency minor units; account balance/hold caches are doctor-verified. Stable cognition action IDs and durable outcomes prevent replayed economic effects or repeated CPU execution. `ResourceDescendants` integrates consent and durable filesystem preparation with conserved separate endowments. Checkpoints already include these tables through full SQLite backup.

`CANCEL_RESOURCE_PURCHASE_REQUEST` delegates requester-authenticated withdrawal to `EconomyService.cancelRequest` through the transactional economic action/cache path. The service queries by request ID and actor UUID, permits only PENDING, and atomically records CANCELLED with one `RESOURCE_PURCHASE_REQUEST_CANCELLED` event. No ledger or reservation operation occurs. A duplicate durable action reuses its result; a fresh duplicate receives a lifecycle rejection. Owner approval/denial/settlement guards already reject this new terminal text status, so no schema migration is required. Integrity compares requester identity with historical creation, verifies cancellation evidence remains terminal and rejects cancellation-linked settlement IDs, purchase holds or settlement ledger entries.

Private request projection is separate from `EconomyService.self()`, which also feeds public presence. `INSPECT_SELF` returns all own pending summaries; cognition packs at most five oldest-first within 600 estimated tokens, alongside a total count, after mandatory observations and before optional history. Summaries contain ID, resource, amount, status, created tick and reason. Terminal records remain historical, and startup/dormancy never withdraws a request. Capital remains actual externally backed money; current cognition supply is Owner allowance/injection or provider free allowance, with no simulated money, exchange rates or payment integration.

Successful cognition output, cursor advancement and a single reserved-credit debit commit together. Pending holds and frozen contexts survive suspension/restart. Direct and continuous cognition acquire exclusive renewable ownership. Only actual sandbox program/tool workloads consume Local Compute; ordinary actions update no execution balance. New reports use resource snapshots and journal consumption; old reports retain historical compute semantics. See the [complete old compute audit](RESOURCE-COMPUTE-AUDIT.md).

## Kernel/content boundary

Source, database, gateway configuration, credentials, Docker policy, quotas, protected tool storage, and adapters are **WORLD KERNEL**. Agent workspaces, shared artifacts, published tool metadata/snapshots, messages, memories, and execution results are **WORLD CONTENT**. World content stored behind the kernel boundary remains inaccessible to direct file actions.
